# 多端统一发布（QuickCopy · Windows / Android / Linux-arm64）

三端（PC、手机、Linux）**版本统一**、**统一发布**：一个 GitHub Release 挂三个产物。
本文是每次发版的执行清单（配套项目规则 `.ohmyagent/AGENTS.md → 发布产物规则`）。

## 1. 版本号同步点（改版本时五处同步）

每次 bump `X.Y.Z` 时，同步改：

| 文件 | 改什么 |
|---|---|
| `src-tauri/Cargo.toml` | `version = "X.Y.Z"` |
| `src-tauri/tauri.conf.json` | `"version": "X.Y.Z"`（前端有改动时顺带 `"url": "index.html?v=N"` 的 N+1） |
| `src-tauri/Cargo.lock` | 由 `cargo build/check` 自动同步（构建一次即可） |
| `mobile-app/pubspec.yaml` | `version: X.Y.Z+b`（b = 构建号，可 = 版本号去掉点的数字） |
| `mobile-app/lib/theme.dart` | `const kAppVersion = 'X.Y.Z'` |

变更日志（changelog）各端维护：
- PC：`src-tauri/src/cmds.rs` 的 `about_info → changelog` 数组顶部插入 `{"v":"X.Y.Z","log":"…"}`
- 手机：`mobile-app/lib/pages/me_page.dart` 的更新日志文本首行加 `vX.Y.Z · …`

## 2. 产物矩阵

| 端 | 产物文件名 | 构建方式 |
|---|---|---|
| PC Windows | `QuickCopy_<ver>_x64-setup.exe` | 本机 `npm.cmd exec tauri build -- --bundles nsis` |
| 手机 Android | `QuickCopy_<ver>.apk` | `mobile-app` 下 `flutter build apk --release`，上传时重命名 |
| Linux arm64 | `QuickCopy_<ver>_arm64.deb` | **GitHub Actions 自动**（tag 触发，无需本地构建） |

## 3. 发布步骤

1. **本地构建 PC + 手机**（产物路径见上），确认两者存在。
2. **提交代码 + bump 版本**（§1 五处 + changelog）。
3. **打 tag 并推送**：
   ```bash
   git tag v<ver>
   git push origin main
   git push origin v<ver>
   ```
4. **等 GitHub Actions（build-deb-linux）跑完**：自动构建 deb 并挂到 Release（约 10 分钟）。
5. **创建 GitHub Release**（在 Actions 挂 deb 之后再创建，或先建 Release 等它挂上）：
   - 上传 PC exe、手机 apk 到同一个 Release。
   - Release Notes 用 **UTF-8 编码**提交（Windows PowerShell 需显式 UTF-8 字节，见旧教训）。
6. 校验：Release 页三个资产齐全、中文无乱码。

## 4. 反例（应避免）

- 只发某一端（如只发 APK 或只发 PC setup）→ 违反统一发布。
- 各端版本号不一致（历史 v0.2.16/v0.2.17 独立递增）→ 已废止，现在统一。
