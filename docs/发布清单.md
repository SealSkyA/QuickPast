# 发布清单（QuickPaste）

每次发版必读。漏掉任何一项都可能造成线上问题。

## 0. 发布前自查

- [ ] 本地已 `cargo build` 通过（gnu 工具链：`$env:RUSTUP_TOOLCHAIN='stable-x86_64-pc-windows-gnu'`）
- [ ] 前端有改动时必须 bump `tauri.conf.json` 的 `"url": "index.html?v=N"`（N+1）
- [ ] 自环功能验证过（QP_AUTO_ACCEPT=1 自动确认，可跳过前端确认链路）
- [ ] 版本号三处一致：`Cargo.toml`、`tauri.conf.json`、`Cargo.lock`（cargo build 自动同步锁文件）

## 1. ⚠️ Release Notes 编码（血泪教训，勿犯）

**发布 GitHub release 时，用 PowerShell 发中文 body 必须显式用 UTF-8 字节发送！**

PowerShell 5.1 的 `Invoke-RestMethod -Body (string)` 默认按**系统 ANSI 编码（GBK）**发送，
GitHub 收到后中文会全部变成乱码（如 "鍒濆鍒濆..."）。v0.2.4 及更早已因此出现乱码。

**正确姿势（唯一可用）：**

```powershell
$body = @{ ... } | ConvertTo-Json
$bytes = [System.Text.Encoding]::UTF8.GetBytes($body)
Invoke-RestMethod -Method Post -Uri $uri -Headers $headers -Body $bytes `
  -ContentType 'application/json; charset=utf-8'
```

- 禁用 `-Body (string)` + 无 charset 的写法。
- 上传 asset（安装包）不受影响（二进制流，用 `-InFile`）。
- 如果发现已有 release 乱码：`PATCH /repos/{owner}/{repo}/releases/{id}` 用 UTF-8 字节重发 body 修复。

## 2. 打包

```powershell
$env:RUSTUP_TOOLCHAIN='stable-x86_64-pc-windows-gnu'
npm.cmd exec tauri build -- --bundles nsis
```

产物：`src-tauri\target\release\bundle\nsis\QuickPaste_<ver>_x64-setup.exe`

## 3. 发布

```powershell
git tag v<ver>            # 如 v0.2.5
git push origin main
git push origin v<ver>
```

- GitHub release 创建 + 上传安装包：见上方 UTF-8 注意项。
- 安装包 asset 名：`QuickPaste_<ver>_x64-setup.exe`。

## 4. 本机安装（静默）

```powershell
Start-Process -FilePath $installer -ArgumentList '/S' -Wait
```

- 安装目录：`%LOCALAPPDATA%\QuickPaste`
- 装完核对注册表 `HKCU:\Software\...\Uninstall\QuickPaste` 的 `DisplayVersion`。

## 5. 发布后

- [ ] GitHub release 页中文正常（不是乱码）
- [ ] 安装包已上传、大小合理（几 MB）
- [ ] 本机安装版启动正常、数据目录 `data/` 完好
